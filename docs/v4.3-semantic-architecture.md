# V4.3 Production Beta 语义调用架构

生产链路中 ResponsePlan 与基础 Claim 由后端确定性建立。正式 API 不实例化 Plan/Claim semantic provider，也不读取 `V43_PLAN_GATEWAY_*`、`V43_CLAIM_GATEWAY_*` 或 `DIFY_API_KEY`。历史 provider 与两份 Dify 文档仅供实验追溯，不发布且没有前端开关。

确定性 ResponsePlan 逐字保存 `requirement_anchor`，不拆分、不改写、不新增实施动作、交付物、验收方式或能力。基础 Claim 使用 Requirement 原文并继续经过 Claim Gate、Coverage 和人工批准。人工 Plan 修改不能变更 REQ-ID、Requirement 原文、anchor 或来源状态，且必须保存前后快照、编辑人、时间与原因。

生产语义调用顺序：

1. `section_drafting`：Writer Workflow，使用 `V43_WRITER_GATEWAY_*`。
2. `targeted_revision`：可选定向修订 Workflow，使用 `V43_REVISION_GATEWAY_*`。

正文 Batch 先经过后端规则 `4.3-batch-routing-1`：只有一条 approved Claim，且没有实施动作、approved Evidence、条件和责任边界时，后端按固定模板直出并记录 `generation_mode=deterministic_template`，不调用 Writer；其余 Batch 记录 `generation_mode=semantic_gateway` 后才允许调用 Writer。生成模式与规则版本保存在任务审计字段中。

需求提取 Workflow 保持不变。正文 Writer 只能消费 approved Claim、approved Evidence、Plan 中逐字 Requirement anchor、conditions 和 mandatory anchors。

## Writer V2 Revision Policy

当前 Beta 的 canonical 路径是 `DocumentGenerationService.generateV2()`：Writer 输出经过
授权、Critical Assertion Guard、装配、Sanitizer 和 Validator 后生成
`pending_review` 版本。该路径不自动调用 `targeted_revision`；验证失败会明确结束为
失败或待人工处理状态。旧 `generate()` 路径中的定向修订逻辑仅保留作兼容/实验用途，
不构成 Writer V2 发布承诺，也不得被当作自动“修作文”兜底。
